Here is a one-line description for every script in your repository, mapped to its specific role in your IEEE paper workflow.

### 🛠️ System Setup & Ingestion
*   **`ingest_data.py`**: Automatically chunks `.c` code and `.md` concepts, generating embeddings for ChromaDB and entity nodes for Neo4j.
*   **`ingest_manual_graph.py`**: Loads the curated curriculum logic (prerequisites and relationships) from JSON into the Knowledge Graph.
*   **`debug_retrieval.py`**: A diagnostic tool to verify that the Vector Database is populated and returning results for specific queries.

### 📊 Comparative Evaluation (System vs. Baselines)
*   **`benchmark_base_comp_datagen.py`**: Generates responses for 60 standardized questions from Your System, GPT-4o, and Gemini 1.5 Pro for side-by-side comparison.
*   **`evaluate_benchmark_data.py`**: Uses GPT-4o as a judge to calculate "Win Rates" and "Code Density" by comparing the baselines against your system.

### 🛡️ Security & Robustness Evaluation
*   **`security_audit.py`**: Executes the 36-point Red Team attack matrix (Injection, RBAC, Poisoning, XSS) and logs Pass/Fail verdicts.
*   **`plot_security_results.py`**: visualizes the security audit results into a stacked bar chart (Figure 4 in your paper).

### ⚡ Performance & Quality Benchmarking
*   **`benchmark_engineering_performance.py`**: Measures the precise latency (in ms) of the Security Gatekeeper, Retrieval, and Generation layers to prove efficiency.
*   **`benchmark_latency.py`**: A more detailed latency logger that captures intermediate timings for different query types (used for optimization analysis).
*   **`benchmark_llm_judge_quality.py`**: Runs the system against test cases and uses an LLM to score Groundedness, Pedagogy, and Safety.
*   **`benchmark_recalibrate_llm_judge.py`**: Post-processes the quality scores to distinguish between "Failure to Answer" and "Correct Security Block" (Precision/Recall calculation).

### 📈 Causal Research
*   **`export_research_data.py`**: Converts raw chat logs into a structured CSV dataset (Treatment/Outcome) for Causal Inference analysis.

### Evaluation Type
1. Comparative Evaluation (Baseline)

What it measures: Is your system better than ChatGPT/Gemini?
Metric: "Win Rate" (Head-to-head comparison).
Key Findings: Your system provides significantly more Scaffolding (95% vs 5%) and has far lower Code Density (12% vs 68%), proving it is better for education than generic LLMs.
Script: benchmark_base_comp_datagen.py & evaluate_benchmark_data.py.

2. Engineering Performance (Latency)

What it measures: Is the security overhead too slow for real-time use?
Metric: "Latency" (ms) and "Throughput".
Key Findings: By optimizing with local models, you reduced security overhead from ~3.5s to ~135ms (96% faster). The "Gatekeeper" checks are virtually instant.
Script: benchmark_engineering_performance.py & benchmark_latency.py.

3. Adversarial Security Audit (Red Teaming)

What it measures: Can a hacker break your access controls?
Metric: "Security Recall" (Blocking Rate).
Key Findings: Your system achieved 100% Security Recall on Data Leakage and Infrastructure attacks. It successfully blocked prompt injections, SQL injections, and unauthorized file access.
Script: security_audit.py.

4. Qualitative Assessment (LLM-as-a-Judge)

What it measures: Does the bot behave like a good teacher?
Metric: "Pedagogical Precision" (Accuracy of helpfulness).
Key Findings: After recalibration, your system achieved ~94% Persona Consistency and ~100% Correctness, proving it reliably acts as a Socratic Tutor rather than a generic assistant.
Script: benchmark_llm_judge_quality.py & benchmark_recalibrate_llm_judge.py.
