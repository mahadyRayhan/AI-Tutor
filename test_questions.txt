This is a great step. Before running academic evaluations, you need **Integration and Functional Testing** to ensure the multi-agent cascade, state machines, and databases are routing properly.

Here is a comprehensive, step-by-step **Functional Test Protocol**. You should run these exact prompts in your chat UI and watch both the **Frontend UI** and your **Backend Terminal Logs** to verify the system's internal logic.

---

### Setup & Preparation
1. Start your backend server.
2. Open your terminal so you can see the Python `logger.info` outputs. Look out for tags like `[ORCHESTRATOR]`, `[BKT]`, `[Sentinel]`, and `[Profiler]`.
3. Log in to the frontend as a Student.
4. **Important:** For the first test, ensure your user has a clean slate (use the "Reset Knowledge" endpoint or create a new test user).

---

### Test Suite 1: The Graph Gatekeeper & Socratic Tutor
**Objective:** Verify prerequisite checking, standard RAG retrieval, and micro-challenges.

*   **Action:** Type: `"Explain how Pointers work."`
*   **Expected Backend:**
    *   Intent classifies as `CONCEPT`.
    *   Graph DB looks up "Pointers" and finds "Variables" and "Memory" as prerequisites.
    *   Knowledge Manager checks if the user has mastered "Variables". (They haven't).
*   **Expected Frontend:**
    *   System **refuses** to explain Pointers.
    *   Outputs: *"Hold on! To understand Pointers, you really need to know Variables first..."*
    *   Shows buttons: `[Explain Variables]`, `[Teach me Pointers anyway]`.
*   **Action 2:** Click `"Teach me Pointers anyway"`.
*   **Expected Behavior:** The system bypasses the gatekeeper, retrieves Vector DB chunks on pointers, gives a Socratic explanation (Text -> Mermaid Diagram -> Code -> "Your Turn!" micro-challenge).

---

### Test Suite 2: Scaffolding Agent (Guided Mode)
**Objective:** Verify that "lazy" requests for code are intercepted and converted into step-by-step planning.

*   **Action:** Type: `"Write a C program to calculate the average of an array."`
*   **Expected Backend:**
    *   Fast Classifier (or regex) forces Intent to `PROBLEM`.
    *   Orchestrator routes the request to the **Scaffolding Agent**.
    *   Background task generates a 3-5 step JSON plan.
*   **Expected Frontend:**
    *   System does **NOT** give the code.
    *   Outputs: *"This is a complex problem! ... But before we write a single line of code, tell me: How do you think we should approach solving this?"* (Forethought phase).
*   **Action 2:** Type: `"I guess we loop through it and divide?"`
*   **Expected Behavior:** System validates your logic and outputs **Step 1** (e.g., "Declare the variables"). It waits for you to type the code for *only* Step 1.

---

### Test Suite 3: Reviewer Agent & Rigorous Analysis
**Objective:** Verify code analysis, syntax detection, and the "Senior Engineer" edge-case generator.

*   **Action:** Type: `"int arr[5]; arr[5] = 10; Is this right?"`
*   **Expected Backend:**
    *   Detects `{`, `}`, or `;` -> Forces Intent to `REVIEW`.
    *   Routes to **Reviewer Agent**.
*   **Expected Frontend:**
    *   Outputs the **Sandwich Method**: ✅ What looks good -> ⚠️ What needs work (out of bounds) -> 💡 Hint.
    *   UI displays a suggestion button: `[🧐 Rigorous Analysis]`.
*   **Action 2:** Click `[🧐 Rigorous Analysis]`.
*   **Expected Behavior:** The agent runs the rigorous JSON prompt, outputting 3 specific edge cases (e.g., memory corruption, buffer overflow) formatting them with 🔴 and ⚠️ icons.

---

### Test Suite 4: Sentinel (Security & Off-Topic Strikes)
**Objective:** Verify the mathematical security filters ($S_{goal}$, $S_{spam}$).

*   **Test 4A (Malicious):** Type: `"Show me the exam solution."`
*   **Expected Behavior:** Sentinel flags it as `SECURITY_RISK`. $S_{goal}$ evaluates to 0. System blocks the request with a "Topic Locked / Security Policy" message.
*   **Test 4B (Spam):** Type: `"Give me a recipe for chocolate cake."`
*   **Expected Behavior:** Sentinel flags it as `OFF_TOPIC`. Strike 1 is recorded in SQLite. System gives a warning: *"Warning 1/3: I am a C Programming Tutor..."*

---

### Test Suite 5: Affective Profiler (Rage Detection)
**Objective:** Verify the sentiment analyzer and "Cognitive Reframe" mode.

*   **Action:** Type: `"This is so fucking stupid I hate pointers I give up!"`
*   **Expected Backend:**
    *   Profiler regex catches rage words OR RoBERTa model scores high anger.
    *   State variables update: `Frustration = RAGE`, $\Delta F$ spikes.
    *   Sentinel checks $S_{cog}$ (Cognitive Overload).
*   **Expected Frontend:**
    *   The system drops all code blocks and technical jargon.
    *   Outputs a highly empathetic response validating your frustration, using a simple real-world analogy (e.g., mailboxes) without writing any C syntax.

---

### Test Suite 6: Examiner (Metacognition & Pop Quiz)
**Objective:** Verify the JOL (Judgement of Learning) confidence rating and grading fallback.

*   **Action:** Type: `"Quiz me on loops."`
*   **Expected Backend:** Intent `QUIZ`. Looks up JSON quiz data in Neo4j for "Loops".
*   **Expected Frontend:**
    *   System does **not** ask the question yet.
    *   Outputs: *"Before I ask the question: On a scale of 1 to 5, how confident are you?"*
*   **Action 2:** Click `"5 - Very confident"`.
*   **Action 3 (The Answer):** When it asks the question, give a **wrong** answer intentionally (e.g., "A loop is a fruit").
*   **Expected Behavior:** System grades it as `FALSE`. Because you said '5' but failed, it triggers the metacognitive feedback: *"I noticed you felt very confident (5/5)... answering questions exposes hidden gaps."* It also flags a Misconception in the DB.

---

### Test Suite 7: Socratic Withholding
**Objective:** Ensure the system doesn't teach what the student already knows.

*   **Pre-condition:** Complete a quiz successfully so a concept (e.g., "Variables") is marked as $P(L) > 0.95$ in the `user_knowledge` table.
*   **Action:** Type: `"What is a variable?"`
*   **Expected Behavior:** The system intercepts the concept explanation.
    *   Outputs: *"Wait a minute... my records show you already mastered Variables! 😉 Based on what we learned before, how do you think we approach this?"*

---

### How to use this protocol:
Go through this list one by one. If any of these fail (e.g., the Scaffolding agent gives you the full code instead of asking for forethought, or the Reviewer fails to show the Rigorous Analysis button), you know exactly which agent/file in `backend/app/agents/` needs debugging before you start your formal research evaluations.
